# BadPunPC_Assistant

游戏商店：[《这是谐音梗》Steam 商店](https://store.steampowered.com/app/4164310/_/)

《这是谐音梗》Windows／Steam 客户端的自动解题助手。通过视觉语言模型（VLM）识别题图、推导谐音答案，再通过本地应用程序接口（API）输入答案、提交和进入下一题。

助手读取游戏可见的题图、分类、字数和答题反馈，不读取题库中的现成答案。游戏需保持运行；成功连接后可以最小化，不占用鼠标和键盘。

## 功能

- “运行控制”和“视觉语言模型（VLM）配置”两个分页；模型配置包含接口地址、模型名称、接口密钥和思考强度。
- 三种运行模式：“猜1题”“猜10题”“一直猜”。每关持续尝试到答对；定量模式完成后停留在最后一题的通关画面。
- 结合汉字和拼音反馈重新猜测；已知条件用自然语言随题图发送，提交前检查字数、排除项和位置要求。
- 游戏试错次数耗尽后重开本关，保留线索；历史保存到本地，重开关卡或重启助手后继续使用。
- 默认使用 DeepSeek 并开启高强度思考；可选择关闭、低、高、最高。界面每次只显示一个最终答案，不显示内部思考。超时或暂时网络故障时自动重试，支持停止。
- Windows 64位免安装程序，启动时不创建终端窗口。

## 下载与安装

从 [最新发行版（Release）](https://github.com/DeianHsu/BadPunPC_Assistant/releases/latest) 下载单个免安装程序 [BadPunPC_Assistant.exe](https://github.com/DeianHsu/BadPunPC_Assistant/releases/latest/download/BadPunPC_Assistant.exe)，放入自己可写的文件夹后直接双击运行，无需解压或安装。发行版只提供这个程序文件。

## 使用

1. 在 Steam 启动《这是谐音梗》，进入中文静态图片的单人关卡。
2. 双击 `BadPunPC_Assistant.exe`。
3. 在“视觉语言模型（VLM）配置”中填写接口地址、模型名称、接口密钥，并选择思考强度后保存。默认档位为“高”。接口应兼容聊天补全（Chat Completions）和图片输入。
4. 在“运行控制”中点击“连接游戏”，选择运行模式，点击“开始自动解题”。
5. 需要结束时点击“停止”。退出助手会停止服务并断开游戏连接。

默认接口为 `https://api.deepseek.com`，模型为 `deepseek-flash`。也可填写其他兼容接口的视觉模型。接口验证功能读取模型列表，不提交游戏答案；“导入已有配置”可以复用已有的 JSON 配置文件。

DeepSeek 的思考强度对应“低”=`low`、“高”=`high`、“最高”=`max`；选择“关闭”时禁用思考。开启时使用服务商默认的推理令牌预算，等待时限至少为180秒；关闭时保留256令牌短答上限和45秒等待时限。停止按钮均可取消正在等待的请求。保存或导入配置会保留已选择的开关与档位，不再强制关闭思考。详见[DeepSeek 思考模式文档](https://api-docs.deepseek.com/zh-cn/guides/thinking_mode/)。

小米官方按量计费的 MiMo-V2.6-Pro 配置如下，接口地址保留 `/v1`，不填写 `/chat/completions`：

| 配置项 | 内容 |
|---|---|
| 接口地址 | `https://api.xiaomimimo.com/v1` |
| 模型名称 | `mimo-v2.6-pro` |
| 接口密钥 | 在小米 MiMo 控制台创建的按量计费密钥 |

助手自动识别官方 MiMo 接口并发送思考开关。MiMo 支持思考开启／关闭；低、高、最高档位仅用于 DeepSeek。关闭思考时使用 `max_completion_tokens` 短答上限，开启时使用服务商默认推理预算。模型名称可手动输入，也可读取模型列表后选择。详见[小米官方调用文档](https://mimo.mi.com/docs/zh-CN/quick-start/summary/first-api-call)。

配置保存到程序旁的 `config.local.json`，保存后用于下一次开始解题。密钥留空时，MiMo 读取 `MIMO_API_KEY` 环境变量，其他接口按配置读取密钥环境变量，默认为 `DEEPSEEK_API_KEY`。日志与历史保存在程序旁的 `runs` 文件夹；发行包不包含个人密钥或运行日志。

## 实现方式

### 游戏连接与题图读取

`badpun.py` 使用 Frida 连接 `BadPunPC.exe`，加载 `agent.js` 和 frida-il2cpp-bridge。桥接脚本通过游戏运行时的类型与对象读取当前题号、分类、字数、题图和答题状态。

题图从游戏纹理导出，根据精灵的矩形区域由 Pillow 裁切，随后编码为图片内嵌地址（data URL）发送给模型。这个流程直接取得题图，不需要截取桌面或识别窗口坐标。

游戏方法调用排入队列，在 Unity 主线程的 `UnitySynchronizationContext.Exec` 中执行。连接期间启用 `Application.runInBackground`，断开后恢复原值，支持游戏失去焦点或最小化后继续处理。

### 模型请求与提示传递

固定提示词说明这是谐音梗题目，答案必须符合分类、字数和全部已知条件；要求只返回含 `answer` 字段的 JSON 对象。每次发送两张题图，第一张图的参考词、分类、答案要求字数及已知条件均用自然语言描述，不再用 JSON 表达题目或约束。

答错后，本地从汉字和拼音反馈中推导排除项、固定位置、禁用位置及数量，将这些条件写成明确的自然语言句子加入请求。同一个汉字或拼音在历史反馈中同时有灰色与橙／绿色时，忽略其灰色反馈，不据此排除、禁用位置或限制数量；橙色换位和绿色固定位置的规则仍保留。只出现灰色的项才整体排除。原始颜色记录、猜过的整词、声调反馈和错误原因不发送给模型。

拦截后立即请求下一次，不追加上一轮回答或纠错对话。失败候选和诊断记录保留在本地，用于拦截重复提交和查看日志。关闭思考时，连续无效返回会自动增加采样变化；开启思考时使用所选档位进行推理。

### 提交与关卡循环

模型返回后，程序检查字数、重复答案、灰字、橙字和绿字位置，再通过游戏自身的拼音字典检查读音条件。符合条件的候选走游戏正常输入和提交流程；题号变化时停止使用过期答案。

答错后收集新的反馈，保存到 `runs/guess-history.json` 并继续请求模型。游戏试错次数耗尽时调用本关正常重载流程，保留历史继续猜测。答对后，“猜1题”和“猜10题”在到数时停止，“一直猜”调用通关按钮进入下一题。

### 本地服务与桌面界面

`desktop_service.py` 管理游戏连接、解题线程和本地 HTTP 服务，`desktop.py` 显示状态、日志和配置。服务默认绑定 `127.0.0.1:18741`，界面关闭时清理连接。

HTTPX 的异步请求设置总等待时限，停止按钮取消等待中的请求；暂时网络故障按短间隔重试。密钥错误、游戏退出等需要处理的问题会显示具体原因。

## 源码运行

准备64位 Python 3.12或更新版本、Node.js 和 npm，然后在项目目录中安装依赖：

```powershell
.\安装依赖.ps1
```

复制示例配置为 `config.local.json`，填写模型配置后启动桌面程序：

```powershell
Copy-Item config.example.json config.local.json
python desktop.py
```

也可以启动本地服务，通过脚本控制：

```powershell
.\启动服务.ps1
.\控制.ps1 -操作 开始 -模式 当前
.\控制.ps1 -操作 开始 -模式 十题
.\控制.ps1 -操作 开始 -模式 连续
.\控制.ps1 -操作 状态
.\控制.ps1 -操作 停止
.\控制.ps1 -操作 关闭服务
```

包管理文件中的标识为 `badpunpc-assistant`；项目、程序及发行文件使用 `BadPunPC_Assistant`。

## 本地 API

默认地址为 `http://127.0.0.1:18741`。服务启动后等待开始请求。

| 方法 | 路径 | 功能／请求体 |
|---|---|---|
| GET | `/health` | 桥接状态、游戏进程编号（PID）与主循环心跳 |
| GET | `/status` | 当前题号、游戏状态和解题进度 |
| GET | `/progress` | 解题进度，不依赖游戏主线程 |
| GET | `/puzzle` | 题面信息和两张题图 |
| POST | `/start` | `{"mode":"current"}` 猜1题；`{"mode":"ten"}` 猜10题；`{"mode":"continuous"}` 一直猜 |
| POST | `/stop` | `{}`，停止 |
| POST | `/shutdown` | `{}`，停止并关闭服务 |
| POST | `/submit` | `{"level_id":"题目ID","answer":"答案"}`，手动提交 |
| POST | `/next` | `{"level_id":"题目ID"}`，通关后进入下一题 |

手动提交和跳题前需要停止自动解题。提交接口检查题号，防止把过期答案送进新题。

## 开发与打包

目录中的主要文件：

| 文件 | 职责 |
|---|---|
| `agent.js` | 游戏进程桥接、题图导出、反馈读取、提交与跳题 |
| `badpun.py` | 模型请求、反馈条件、解题循环、本地 API |
| `desktop_service.py` | 桌面配置与服务生命周期 |
| `desktop.py` | 桌面界面 |
| `build_app.py` | 程序和便携压缩包的构建 |
| `config.example.json` | 默认配置 |
| `tests/` | 针对性流程验证 |

安装构建依赖后打包：

```powershell
python -m pip install --target .build-deps PyInstaller==6.22.3
python build_app.py
```

生成 `release/BadPunPC_Assistant.exe`，GitHub 发行版仅上传这个文件。构建时另保留使用说明、第三方许可证及本地便携压缩包。窗口模式不创建终端；普通窗口启动器缺失时可以使用 PyInstaller 已安装的官方窗口诊断启动器。`python build_app.py --folder` 生成目录预览包。

检查不连接游戏、不调用外部模型的成品启动流程：

```powershell
.\release\BadPunPC_Assistant.exe --smoke-test .\build\smoke.json
```

## 支持范围与验证

当前支持中文静态图片的单人关卡；已适配本机 Steam 构建 `25649557`、Unity `2022.3.62f3c1`、元数据版本31。游戏更新后内部类名或方法可能变化，需要重新适配。

已验证真实题图导出、模型猜测后的正常提交与通关跳题、游戏最小化后的题图读取，以及配置保存、三种模式、无效答案拦截、反馈传递、超时、停止和窗口版打包。失败重开保留提示已做模拟流程验证，未故意耗尽游戏尝试进行实机回归。

尚未统计大量关卡的准确率；持续尝试不保证模型能解出每道题。仅支持图片输入的模型，文本模型无法完成识图流程。
